# Chain registries — verify before you trust

These JSON files are the **single source of on-chain addresses** for the whole system (contracts read
them in tests/deploys; the off-chain SDKs load them at runtime). Nothing in `src/` hardcodes an address.

## The verification convention (read this)

> **A wrong address here can drain funds. We never guess addresses.**

Every address entry carries a `_verify` flag:

```jsonc
"weth":  { "address": "0x4200...0006", "_verify": false, "_source": "OP Stack predeploy docs" },  // ✅ confirmed
"aaveV3":{ "pool": { "address": "0x0000...0000", "_verify": true }, "_note": "confirm Aave V3 Pool" } // ❌ placeholder
```

- `"_verify": false` + a `"_source"` URL → **confirmed**; safe to use.
- `"_verify": true` and/or a **zero address** → **unconfirmed placeholder**; treat as unknown. Live code
  paths and the SDK config loader must refuse to use it.

### What is pre-filled vs. left as a placeholder
- **Pre-filled (confirmed):** addresses that are genuine cross-chain constants or protocol predeploys —
  Permit2, Multicall3, the Balancer V2 Vault (constant where deployed), OP-Stack predeploys (WETH,
  GasPriceOracle, L1Block), and Arbitrum precompiles (ArbGasInfo, ArbSys). These are the same regardless
  of chatter and are cited.
- **Placeholder (`_verify: true`, address `0x00…00`):** everything chain-specific — Aave V3 Pool, DEX
  factories/routers/quoters/PoolManagers, and token addresses (USDC/USDT/DAI, etc.). Even where a value
  is "well known", it is left blank on purpose so a human/agent confirms it against an authoritative
  source before it can move money. `decimals` and `symbol` metadata are filled in as hints.

## How to verify (Ralph "research" mode, or a human)
1. Find the address in the protocol's **official deployment registry / docs** or the chain's **block
   explorer for the verified contract**. For anything that moves funds, corroborate with a second
   independent source.
2. Set `"address"`, flip `"_verify": false`, and add `"_source": "<url>"`.
3. If a protocol is **not** deployed on a chain, set the provider/dex `"available": false` with a note —
   do not invent an address.
4. Reflect confirmed availability in the relevant `docs/specs/` capability matrix and commit.

See `ralph/prompts/research.md` for the exact loop procedure. The worklist of everything still unverified
is generated by `scripts/verify.sh` (task P0-T5) so you always know what's left.

## Schema
All files validate against `schema.json` (draft 2020-12). Validation is wired into `scripts/verify.sh`
in task **P0-T4**. Keep every file `$schema`-referenced and valid.
